# Personal Portfolio — Atandrit Chatterjee

A single-page portfolio for a software engineer moving into product — positioned
for **Associate Product Manager** roles, with a built-in admin panel so every
word on the site can be changed from a browser without touching code.

[![HTML5](https://img.shields.io/badge/HTML5-E34F26.svg?logo=html5&logoColor=white)](https://developer.mozilla.org/en-US/docs/Web/HTML)

No frameworks, no build step, no server. It deploys as static files on GitHub Pages.

---

## The one thing to know

**`content.js` is the entire site.** Every heading, paragraph, bullet, tag and
link lives in that one file, and `index.html` is only a skeleton of mount points.

You should never edit `content.js` by hand. Open **`admin.html`**, make your
changes in a form, and press **Publish** — the panel commits the new
`content.js` straight to GitHub and Pages redeploys it.

---

## Files

| File | What it's for |
|---|---|
| `index.html` | Page skeleton, plus the SEO and share-preview `<meta>` tags |
| `content.js` | **All site content.** Generated by the admin panel |
| `script.js` | Renders the page from `content.js`; handles the contact form |
| `style.css` | Public site styling, light + dark themes, print layout |
| `admin.html` / `admin.js` / `admin.css` | The admin panel — never loaded by the public page |
| `site.webmanifest` | Icons and metadata for "add to home screen" |
| `assets/` | Photo, `resume.pdf`, favicon set, `og-image.png` share card |

## Running it locally

`content.js` is a plain `<script>` rather than JSON specifically so the site
works when opened straight off disk — double-clicking `index.html` is fine.

For the admin panel's Preview button to work you want a real server:

```bash
# from the project folder
python -m http.server 8899
# then open http://localhost:8899/
```

Or use the **Live Server** extension in VS Code / Cursor.

## Editing the site

Open `admin.html` (locally, or at `your-site-url/admin.html`).

### Every-day use

The bar at the top of the editor holds the two things that change most often:
your **job-hunting status** — open to work / open to the right role / not
looking, which sets the colour of the dot on the hero pill and swaps in a
matching headline — and whether that pill shows at all. If you've written your
own headline, changing status leaves it alone.

### What's in the sidebar

Everything else is grouped down the left. Lists can be reordered and deleted.

- **You** — Availability, Profile & hero, Key numbers, About
- **The pitch** — How I got here, Why hire me
- **Product thinking** — Principles, Experience, Case studies, Products built,
  Teardowns, Experiments, Frameworks, Observations, What I'm learning
- **The rest** — Skills, Product writing, Education, Courses & certs, Contact,
  Links
- **Plumbing** — Search & sharing (SEO), Settings, Footer

### Sections hide themselves when empty

A section with nothing in it is hidden on the live site, and its nav link
disappears with it, so a heading is never left stranded above nothing. That
currently applies to **case studies, teardowns, experiments, frameworks,
observations, what I'm learning, product writing** and **courses &
certifications**. They're empty on purpose — add one entry and the section
appears.

That's also the honest state of this portfolio: the scaffolding is built, but
the sections that do the most work are waiting on writing only you can do.

| Section | What makes it land |
|---|---|
| Case studies | Pick a product you use, find something genuinely broken, and show problem → evidence → root cause → what you'd build → how you'd prioritise → metrics → risks. One done properly beats five done thinly. |
| Teardowns | Value proposition, journey, growth loops, and what you'd *remove*. Cutting is harder than adding, so that answer gets read closest. |
| Experiments | Something you actually built and the real numbers, including the failures. "Demand existed, retention was weak" beats a vague success. |
| Observations | One short note a week about a product you use. Nobody fakes a hundred of these, which is exactly why they work. |

Two rules worth keeping: only list frameworks you have really used, and keep
the left column of **Why hire me** genuinely honest. A hiring manager already
knows what's missing from your CV, and naming it yourself is what makes
everything else on the page believable.

### Preview, backup, discard

**Preview** stashes your unpublished draft in `sessionStorage` and opens the
real page at `index.html?preview=1`, rendered from that draft and marked with a
banner. **Download backup** saves a copy of `content.js` to your machine.
**Discard changes** rolls back to the version you loaded. Closing the tab with
unsaved edits prompts first.

### Offline mode

**"Edit offline and download the file instead"** on the Connect screen opens the
editor with no token at all. Publishing and resume upload are disabled; you make
your changes, hit **Download backup**, and commit that `content.js` yourself.
Useful on a machine where you'd rather not paste a token.

### Publishing

Publish writes two files:

1. `content.js` — the content itself.
2. `index.html` — but only the SEO and share-preview tags. Crawlers for LinkedIn,
   Slack and WhatsApp don't run JavaScript, so those values have to be real HTML.
   The panel rewrites them in place; the `data-seo` attributes in `index.html` are
   how it finds them, so leave those attributes alone.

GitHub Pages takes roughly 30–60 seconds to rebuild. A hard refresh
(<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>R</kbd>) clears the cached old version.

## One-time setup

### 1. GitHub access token

The admin panel needs permission to commit to this repository.

1. Go to [github.com/settings/personal-access-tokens/new](https://github.com/settings/personal-access-tokens/new).
2. Create a **fine-grained** token.
3. Under *Repository access*, choose **Only select repositories** → this one.
4. Under *Permissions → Repository permissions*, set **Contents: Read and write**.
   Grant nothing else.
5. Paste it into the admin panel's Connect screen.

Leave **"Remember this token on this device"** unticked on any shared computer —
when unticked the token is kept only for the current browser session.

> The token lives in your browser, never in this repository. Because it's scoped
> to one repository with one permission, the worst case if it leaks is someone
> editing this site — not your account. Revoke it from the same settings page
> at any time.

### 2. Contact form

Live. A Web3Forms access key is set in `config.web3formsKey`, so submissions are
emailed straight to the address registered with that key. There's no database
and no backend. The form also has a honeypot field and client-side validation.

To point it at a different inbox, confirm a new address at
[web3forms.com](https://web3forms.com), copy the access key, and paste it into
**Settings → Contact form delivery** in the admin panel. Use **Send myself a
test message** to check it, then Publish.

The key is safe to keep in this repository — Web3Forms keys are designed to sit
in public client-side code and only allow posting to your own form. If a key
ever starts attracting spam, generate a new one and replace it.

If the key is ever blank, or the request fails, the form falls back to opening
the visitor's own email app with the message pre-filled, so it's never a dead
end.

### 3. Resume

**Settings → Resume file** replaces `assets/resume.pdf` in place, up to 5 MB.
Every download button on the site points at that same path, so links you've
already shared in emails keep working. Update the *"last updated"* label at the
same time.

Note this one commits **immediately** rather than waiting for Publish — the PDF
goes straight to the repository as soon as you press Upload.

## Features

**Positioning**
- Availability pill with a live status dot, editable without touching code
- Metrics band — the numbers a recruiter remembers after ten seconds
- A hero that states the transition plainly rather than claiming a title
- Structured case studies, teardowns and experiments, so the interesting part is
  the reasoning rather than the tech stack
- A "why product management" story section instead of a paragraph of clichés
- A **what I lack / what I bring** ledger that names the experience gap directly
- Every section hides itself until it has content, so the page is never padded

**Engineering**
- Dark mode that respects `prefers-color-scheme`, applied before first paint so
  there's no flash of the wrong theme
- Reveal-on-scroll via Intersection Observer, gated on an `html.js` class so
  content is never stuck invisible if JavaScript fails
- Scroll-progress bar, scroll-spy nav highlighting, collapsing mobile menu
- Skip link, visible focus rings, `aria-live` form status, labelled controls
- Open Graph + Twitter cards + JSON-LD `Person` schema
- Print stylesheet that collapses the page into a readable one-pager
- All rendered content is HTML-escaped and link targets are scheme-checked

**Admin panel**
- Forms generated from a single `SCHEMA` array — adding a section means adding
  one entry there, one block in `index.html`, and one render function
- Missing branches are seeded from that same schema on load, so an older backup
  can't crash the editor
- Reads and writes through the GitHub Contents API; no server of its own

## Regenerating the favicons

The icon set is derived from the AC monogram in `assets/ac-logo-source.webp`.
`assets/` already contains everything the site needs, so this is only necessary
if the logo changes. Requires Python with Pillow:

```python
from PIL import Image, ImageChops
src = Image.open('assets/ac-logo-source.webp').convert('RGB')
r, g, b = src.split()
darkest = ImageChops.darker(ImageChops.darker(r, g), b)
# White background out, tight-crop, then LANCZOS down to each size.
# The downscale is what re-creates the antialiased edge.
```

The share image (`assets/og-image.png`) is 1200×630. If you replace it, keep
those dimensions or the LinkedIn preview will letterbox.

## Deploying

Settings → Pages → deploy from branch `main`, folder `/ (root)`. Then set the
live URL in **Settings → Live site URL** in the admin panel and publish once, so
the canonical and share-preview links point at the right place.
